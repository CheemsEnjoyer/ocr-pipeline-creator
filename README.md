# OCR Flow Studio

Конструктор OCR-пайплайнов и обработка документов. Интерфейс — React/Vinext, API — Python/FastAPI, база — SQLAlchemy + SQLite. В левом меню доступны обработка, конструктор, пайплайны, история документов и API-ключи. Интерфейс закрыт логином и паролем администратора, внешние системы подключаются через отдельные API-ключи.

В разделе «Пайплайны» бокового меню отображаются сохранённые конфигурации. Нажмите на название, чтобы отредактировать настройки и сохранить тот же пайплайн, или на корзину, чтобы удалить его с подтверждением. Список обработки обновляется автоматически. Удаление пайплайна не удаляет документы из истории. Пайплайны хранятся в текущем браузере.

## Запуск

Нужны Node.js 22.13+ и Python 3.10+ (при установке Python на Windows включите **Add Python to PATH**).

```powershell
npm install
npm run dev
```

При первом запуске автоматически создаётся `.venv` и устанавливаются Python-зависимости. Затем поднимаются Python API и интерфейс. Повторные запуски не переустанавливают зависимости, пока `backend/requirements.txt` не изменится. Активация виртуального окружения и ручные SQL-команды не нужны.

Откройте http://localhost:5173. Остановка обоих серверов — `Ctrl+C`.

## LiteLLM

Скопируйте `.env.example` в `.env`, задайте `LITELLM_BASE_URL` и при необходимости `LITELLM_API_KEY`. Адрес может быть с `/v1` или без него. Ключ использует только Python-сервер.

Если в старом `.env` осталась строка `DATABASE_URL=postgresql://...`, удалите или закомментируйте её для использования SQLite по умолчанию. Старые `OBJECT_STORAGE_*` больше не используются.

Для корпоративного прокси задайте `PROXY_URL` в `.env` — один адрес на все исходящие запросы: внешний OCR-сервис, LiteLLM и установку Python-зависимостей. Например `PROXY_URL=http://user:password@proxy.company.local:8080`. Адрес без протокола автоматически дополняется `http://`, поддерживаются схемы `http`, `https`, `socks5`; значение с другой схемой игнорируется с предупреждением в логе. Исключения перечисляйте в `NO_PROXY` (например `localhost,127.0.0.1`).

`PROXY_URL` перекрывает `HTTP_PROXY` и `HTTPS_PROXY`; если он не задан, эти переменные по-прежнему работают. Какой прокси применён, видно в тексте ошибки 502 и в предупреждении в логе сервера — там указаны адрес запроса и прокси. Ошибки сертификатов исправляйте настройкой доверенного корпоративного CA (например, `SSL_CERT_FILE`); проверка TLS остаётся включённой.

## Доступ и API-ключи

Интерфейс и API закрыты. В интерфейс входят по логину и паролю администратора: задайте `OCR_ADMIN_LOGIN` и `OCR_ADMIN_PASSWORD` в `.env` (пароль не короче 8 символов). Без `OCR_ADMIN_LOGIN` логин — `admin`. Без `OCR_ADMIN_PASSWORD` сервер при первом запуске генерирует пароль и сохраняет его в `data/admin-password.txt`; путь пишется в лог. После входа браузер получает сессию на 12 часов (cookie `HttpOnly`, `SameSite=Strict`); при работе по HTTPS добавьте `OCR_SECURE_COOKIE=1`. Смена логина или пароля завершает все открытые сессии.

Пароль хранится только в `.env` или в файле, в базе — лишь его медленный хэш (scrypt) для привязки сессий. После 10 неудачных попыток за 10 минут вход блокируется до конца этого окна. Счётчик общий для всех клиентов: пока идёт перебор, войти не сможет и настоящий администратор.

Для внешних систем на странице «API-ключи» создаётся отдельный ключ на каждую интеграцию, с выбором доступных ей пайплайнов. Сам ключ показывается один раз — в базе хранится только его SHA-256-хэш. Список пайплайнов у ключа можно изменить, а ключ — отозвать. Ключ передаётся в заголовке `Authorization: Bearer ...` и разрешает только:

- `GET /api/v1/pipelines` — назначенные ключу пайплайны;
- `POST /api/v1/pipelines/{id}/run` — обработка документа из поля формы `file`;
- `POST /api/v1/pipeline/run` с полями `file` и `pipeline_id` — то же самое.

`/v1` — версия API интеграций. Если его придётся менять несовместимо, новая версия появится под `/api/v2`, а `/api/v1` продолжит работать как прежде. Адреса без версии (`/api/pipelines`, `/api/pipelines/{id}/run`, `/api/pipeline/run`) тоже остаются рабочими: ими пользуется интерфейс и уже подключённые системы. Служебные разделы — ключи, документы, вход — под `/api/v1` не публикуются.

Передать свою конфигурацию пайплайна, открыть историю документов, настройки или другие ключи с ключом интеграции нельзя — сервер отвечает 403. Отозванный ключ получает 401. Пароль администратора в заголовке `Authorization` не принимается — только ключи интеграций.

```bash
curl -H "Authorization: Bearer ocr_..." -F "file=@scan.pdf" http://127.0.0.1:5173/api/v1/pipelines/pl_.../run
```

## Хранение

- `data/ocr.sqlite3` — история, распознанный текст, первоначальный ответ модели и отредактированные поля.
- `data/originals/` — исходные файлы под внутренними UUID.
- `data/admin-password.txt` — сгенерированный пароль администратора, если `OCR_ADMIN_PASSWORD` не задан.
- Пайплайны доступны через API; при открытии списка ранее сохранённые конфигурации из браузера автоматически импортируются на сервер.

Таблицы создаются автоматически при старте через `Base.metadata.create_all()`. Перезапуск сохраняет имеющиеся данные. Этот механизм создаёт отсутствующие таблицы, но не изменяет столбцы существующих таблиц при будущих изменениях моделей: для таких изменений потребуется обновление схемы либо новая база.

Старая D1-база и R2-файлы автоматически не переносятся и не удаляются. Новая история начинается с SQLite. Для резервной копии остановите приложение и скопируйте всю папку `data`. Путь можно изменить через `OCR_DATA_DIR`. Данные общие для пользователей одного экземпляра приложения.

## Обработка и история

`POST /api/pipeline/run` принимает файл (до 20 МБ) и конфигурацию пайплайна. Текстовые файлы читаются в UTF-8, PDF с текстовым слоем — через pypdf, DOCX — через python-docx. Сканы отправляются в выбранную vision-модель LiteLLM или в OCR-сервис, адрес которого указывается в мастере. Вместе с файлом уходят поля формы из `ocr.options` пайплайна, если они там заданы (например `model_name` и `force_ocr`). Текст берётся из `page_content`, `text` или `result` ответа. Для внутреннего сервиса при заданном `PROXY_URL` добавьте его хост в `NO_PROXY`. Опциональный шаг извлечения возвращает JSON.

Успешно обработанный документ появляется в `/history`. Можно открыть исходник (PDF и изображения), скачать файл, прочитать распознанный текст и изменить поля. Изменения не затрагивают оригинал и исходный ответ модели. Конфликтующие правки из другой вкладки возвращают HTTP 409.

## Архитектура и команды

- `backend/main.py` — FastAPI, жизненный цикл базы и API документов.
- `backend/database.py` — модель SQLAlchemy и создание соединений.
- `backend/processing.py` — чтение документов, OCR и LiteLLM.
- `app/api/[...path]/route.ts` — передача запросов из интерфейса в Python без CORS.
- `scripts/run-app.mjs` — подготовка Python и управление двумя серверами.

```powershell
npm run backend:setup # только подготовка Python
npm run test:backend  # API-тесты на временной базе, без реальных вызовов LiteLLM
npm run build         # сборка интерфейса
npm start             # Python + собранный интерфейс
```

Python API слушает `127.0.0.1:8000`, интерфейс — `127.0.0.1:5173`. Порты можно изменить через `BACKEND_PORT` и `PORT`. `BACKEND_URL` позволяет направить интерфейс к отдельно размещённому API. Для отдельного запуска Python: `.venv\Scripts\python.exe -m uvicorn backend.main:app --host 127.0.0.1 --port 8000` (Linux/macOS: `.venv/bin/python`).

Развёртывание требует обычного сервера с Node.js и Python и постоянным диском для `data`. Старый сценарий публикации в Cloudflare Workers/Sites больше не используется. Для доступа извне поставьте reverse proxy с HTTPS перед портом интерфейса и задайте `OCR_SECURE_COOKIE=1`; порт Python API наружу не открывайте.


## Список пайплайнов для интеграции

`GET /api/pipelines` возвращает `{"pipelines": [...]}`. Каждый элемент содержит
`id`, `name`, `source`, `ocr`, `extraction`, `createdAt` и `updatedAt`.
В `ocr` и `extraction` сохраняются настройки моделей, температуры, промпты и поля.
Пустой список возвращается как `{"pipelines": []}`.

Получите список, выберите нужный элемент и передайте его целиком как JSON-строку
в поле формы `pipeline` вместе с `file` в `POST /api/pipeline/run`.
Запуск по одному ID пока не поддерживается.

Конструктор сохраняет конфигурации через `POST /api/pipelines` и
`PATCH /api/pipelines/{id}`; удаление — `DELETE /api/pipelines/{id}`.
Старые пайплайны импортируются при первом открытии списка в исходном браузере;
до этого сервер не может прочитать данные этого браузера. Импорт не перезаписывает
существующие серверные конфигурации и не восстанавливает удалённые.
